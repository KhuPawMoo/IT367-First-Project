Git Commands Study Guide

A beginner-friendly guide to understanding Git, GitHub, commits, branches, merging, and remote repositories.
Big idea: Git is a version-control system. It lets you save versions of your project, see what changed, go back to older versions, and work with other people.

1. Git vs. GitHub

Git

Git is the software that tracks changes in your files on your computer.

GitHub

GitHub is an online service where Git repositories can be stored and shared.

GitGitHub
Runs on your computer Runs online
Tracks versions Hosts repositories
Works without internet for most local operations Useful for collaboration and backup

2. The Git Workflow

The most important workflow to remember is:

Working Directory
→
Staging Area
→
Repository
→
Remote / GitHub
StageMeaning
Working Directory The files you are currently editing.
Staging Area Files you selected to include in the next commit.
Repository The local Git history containing your commits.
Remote An online repository, commonly on GitHub.

3. First-Time Git Setup

git --version

Checks whether Git is installed.

git --version

git config --global user.name

Sets the name Git records in your commits.

git config --global user.name "Your Name"

git config --global user.email

Sets the email Git records in your commits.

git config --global user.email "you@example.com"
Important: Your Git commit identity is not the same thing as your GitHub password.

4. Create or Download a Repository

git init

Turns an existing folder into a Git repository.

cd my-project
git init

git clone

Downloads an existing remote repository to your computer.

git clone https://github.com/username/project.git

5. Check What Git Sees

git status

One of the most useful Git commands. It tells you which files are modified, staged, or untracked.

git status

Example situation:

modified:   main.py
untracked:  notes.txt

This means main.py has changed and notes.txt is a new file Git is not tracking yet.

6. Add Files to the Staging Area

git add filename

Adds one file to the staging area.

git add main.py

git add .

Adds all changed and untracked files in the current directory.

git add .
Think of git add as saying: "I want these changes included in my next snapshot."

7. Commit Your Changes

git commit -m "message"

Creates a permanent snapshot in your local Git history.

git commit -m "Add login page"

A good commit message briefly explains what changed.

Typical sequence: 
git status
git add .
git commit -m "Describe my changes"

8. View Commit History

git log

Shows your commit history.

git log

git log --oneline

Shows a shorter version of the history.

git log --oneline

9. See What Changed

git diff

Shows changes that have not been staged yet.

git diff

git diff --staged

Shows changes that are already staged.

git diff --staged

10. Branches

A branch lets you work on a separate line of development without immediately changing the main branch.

git branch

Lists local branches.

git branch

git branch feature-login

Creates a new branch.

git branch feature-login

git switch feature-login

Switches to a branch.

git switch feature-login

git switch -c feature-login

Creates a new branch and switches to it immediately.

git switch -c feature-login

11. Merge Branches

git merge branch-name

Combines another branch into your current branch.

git switch main
git merge feature-login

Here, the changes from feature-login are merged into main.

Merge conflict: A conflict can happen when Git cannot automatically decide how two branches' changes should be combined. You must edit the affected file, resolve the conflict, then stage and commit the result.

12. Remote Repositories

git remote -v

Shows the remote repository addresses connected to your project.

git remote -v

git remote add origin URL

Connects your local repository to a remote repository.

git remote add origin https://github.com/username/project.git

13. Push: Send Your Commits to GitHub

git push

Sends your local commits to the remote repository.

git push

git push -u origin main

Pushes the main branch and sets its upstream remote branch.

git push -u origin main

After the upstream is configured, you can usually use:

git push

14. Pull: Get Changes from GitHub

git pull

Downloads remote changes and integrates them into your current branch.

git pull
Simple memory trick:
push = send my commits up
pull = bring remote changes down

15. Fetch vs. Pull

CommandWhat it does
git fetch Downloads information about remote changes without automatically merging them into your current branch.
git pull Fetches remote changes and then integrates them into your current branch.

16. Undoing Changes

git restore filename

Discards unstaged changes in a file, returning it to the version from the current commit.

git restore main.py
This can permanently discard your uncommitted changes in that file. Use it carefully.

git restore --staged filename

Removes a file from the staging area without deleting its changes.

git restore --staged main.py

git revert COMMIT_ID

Creates a new commit that reverses the effect of an earlier commit.

git revert abc1234

18. The Most Important Workflow to Memorize

If you changed code and want to save it to GitHub:

# 1. Check what changed
git status

# 2. Stage your changes
git add .

# 3. Create a commit
git commit -m "Describe what I changed"

# 4. Send the commit to GitHub
git push

19. Example: A Small Python Project

Imagine you have:

my-project/
├── main.py
├── requirements.txt
└── README.md

You create a Git repository:

cd my-project
git init

You edit main.py, then:

git status
git add main.py
git commit -m "Update main program"

Later you add a new feature:

git switch -c feature-api
# edit files
git add .
git commit -m "Add API feature"

Then return to main and merge:

git switch main
git merge feature-api

Finally, send the result to GitHub:

git push

20. Beginner Mental Model

Remember these four words:
  1. Change — edit your files.
  2. Add — choose changes for the next commit.
  3. Commit — save a version in Git history.
  4. Push — send your commits to the remote repository.

21. Practice Exercise

Try this sequence in a test folder:

mkdir git-practice
cd git-practice
git init

echo "# Git Practice" > README.md

git status
git add README.md
git commit -m "Add README"

git log --oneline

git switch -c test-branch

echo "Learning Git" >> README.md

git add README.md
git commit -m "Update README"

git switch main
git merge test-branch

git log --oneline

On some systems, the default branch may be named master instead of main.
